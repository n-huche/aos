# Aprendizagem

Como transformar material de estudo em habilidade. Sem calendário — o ritmo é seu.

Prioridade: prática deliberada no artefato do projeto vence qualquer método que atrase o envio. Se um ritual (Anki longo, reassistir playlist) compete com esse artefato, **corte o ritual**.

---

## Princípios

- **Active recall / retrieval practice** — Depois do material, feche e explique ou refaça *sem olhar*. Testar a memória fortalece mais do que reler.
- **Spaced repetition** — Revisar ~1d / ~3d / ~7d. Não é só flashcard: *refaça* um pedaço pequeno ou responda a nota Q→A.
- **Deliberate practice** — Meta estreita, fora da zona de conforto, feedback rápido (compila? o teste passa? o movimento sai?). Consumir mais material sem stretch não é prática deliberada.
- **Worked example → faded guidance** — Iniciante: estude o exemplo passo a passo. Depois: complete o próximo passo sozinho. Depois: faça a fatia no projeto sem o material. Guia some conforme a expertise sobe.
- **Block → interleave** — Isolar um conceito novo. Depois misturar o que você confunde. Interleaving dói mais e retém melhor.
- **Generation effect** — Tente gerar a resposta *antes* de ver a solução. Errar com esforço > colar certo.
- **Dual coding (leve)** — Um diagrama minúsculo + texto. Sem obsessão com mapa bonito.
- **Desirable difficulties** — Se a sessão parece fácil demais, falta retrieval, spacing ou stretch. Dificuldade *indesejável* (assunto fora do escopo do projeto atual) só atrasa.
- **Read → Trace → Modify → Write** — Leia; acompanhe o fluxo; mude um detalhe; só então faça do zero.
- **Feynman / rubber duck** — Explique em voz alta. Se travar, ainda não sabe.
- **“Consigo fazer sem o material?”** — critério de ouro. Se não, volte ao fade, não ao binge.

---

## Anti-padrões

- Horas de material, zero artefato
- Grifar/anotar sem recall fechado (ilusão de competência)
- Reassistir no piloto automático — prefira pause + predizer + fazer
- Tutorial hell: copiar o exemplo e nunca portar para o seu projeto
- Colecionar fontes — 1 principal + no máximo 1 complementar por tópico
- Maratona sem retrieval — blocos 25–50 min com recall no fim
- Repo/caderno paralelo a cada tutorial — tudo converge no projeto ativo
- Polir teoria fora de escopo antes da fatia hireable/útil do projeto

---

## Protocolo de sessão (25–50 min)

### Antes (2–3 min)
1. Meta em 1 frase
2. Abrir o artefato do projeto (não um rascunho descartável)
3. Escolher o trecho de material alinhado à meta; pular o que está fora de escopo

### Durante
1. **Pause + predict** — o que vem no próximo passo?
2. **Trace** — acompanhe o fluxo mentalmente
3. Não pause 40 min para copiar — anote ganchos; o trabalho real é closed-book depois
4. Tópico novo e denso: material como worked example, não ditado

### Depois
Closed-book recall → fatia no projeto → nota/flashcards → agendar review.

Se o timer acabou e você só consumiu material, a sessão **não contou**. Estenda ~15 min para retrieval + 1 mudança mínima, ou marque incompleta.

---

## Depois do material (obrigatório)

- [ ] Explicar sem olhar (2–5 min): o que mudou? por quê? onde no projeto vive?
- [ ] Uma fatia minúscula no artefato — commit ou registro claro
- [ ] 3–5 flashcards **ou** 1 nota Q→A (perguntas de *decisão*, não só definição)
- [ ] Review ~1d / ~3d / ~7d: refazer ou responder Q→A, não reassistir o material inteiro
- [ ] “Consigo fazer sem o material?” Se não → fade amanhã, não fonte nova

## Como saber que já sabe

Não é “terminei o vídeo/capítulo”.

| Tipo | Já sabe quando… |
|---|---|
| Conceito | Explica com exemplo próprio; reproduz closed-book; aponta o erro comum em ~30s. |
| Ferramenta / fluxo | Executa o fluxo completo sem tutorial e explica o porquê de cada passo. |
| Modelo / protocolo | Desenha o esquema de cabeça; aplica a um caso novo do projeto. |
| Framework / técnica | Adiciona a fatia no projeto sozinho; sabe o que quebra e como validar. |
| Teste / verificação | A verificação falha pelo motivo certo, depois passa; nomeia pelo comportamento. |

Sinal vermelho: só reconhece a tela do material; copia e torce; não adapta ao domínio do projeto.

## Protocolos por tipo de tópico

Use a receita do **tipo**, não um método genérico para tudo.

### Conceitos
Blocos curtos; pause + predizer; fade rápido para exercícios no domínio do projeto. Falha comum: overlearn de sintaxe/definições sem aplicar.

### Ferramentas e fluxos
Mãos na ferramenta *durante* o material; o exame é repetir o fluxo sozinho depois. Falha comum: assistir como teoria.

### Modelos e protocolos
Trace um caso real; desenhe; aplique no projeto (não só no slide). Falha comum: decorar regras sem usar.

### Framework / técnica hands-on
Worked example → fade → implementar no projeto sem o material. Pule demos fora de escopo. Falha comum: tutorial hell sem portar.

### Teste / verificação
Ciclo falha → passa → refatora. Verifique o comportamento, não a implementação linha a linha.

---

## Ligação com o projeto

Toda sessão deve **deixar algo no artefato alvo**. Não abra um paralelo “só para acompanhar”. Se o método atrasa o próximo passo útil, corte o método.

---

## Nota Q→A

```markdown
# [Tópico] — [fatia concreta]

## Meta da sessão
Uma frase.

## Q → A
**P:** …?
**R:** … (suas palavras; 3–8 linhas)

## Onde no projeto
Arquivos / partes tocadas.

## Armadilha
O erro que quase cometi / o que o material omitiu.

## Review
1d: ____  3d: ____  7d: ____
```

**Flashcard:** frente = decisão ou reconstrução; verso = resposta curta + 1 exemplo do projeto. Limite 3–5 por sessão.

---

## Definition of done

1. Meta escrita *antes*
2. Retrieval closed-book
3. Mudança no artefato do projeto *ou* nota Q→A + passo reproduzível
4. Cards ou nota Q→A
5. Reviews 1d / 3d / 7d anotados
6. “Consigo fazer sem o material?” — sim / parcial

Se 2–3 falharam, foi exposição, não aprendizado.
